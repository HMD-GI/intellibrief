# 天气模块人工测试清单

## 一、准备工作
1. 在项目根目录 `.env` 中按需配置：
   - `WEATHER_PROVIDER=auto`
   - `QWEATHER_API_KEY=你的和风天气 Key`（可选，配置后可获取预警和台风）
2. 启动后端：
   - `.\venv\Scripts\python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8000`
3. 启动前端：
   - `cd frontend`
   - `npm run dev`

## 二、天气页面测试
1. 打开前端页面，点击左侧“天气情况”。
2. 输入地区，例如：
   - `北京`
   - `上海浦东`
3. 点击“保存地区并查询”。
4. 检查：
   - 页面顶部显示当前地区、当天日期、天气源。
   - 当使用和风天气失败或未配置 Key 时，页面会出现“已自动切换备用天气源”说明。
   - 下方显示逐小时天气、温度、湿度、风向风力、降水概率。
   - 台风区域显示真实台风数据，或显示“当前使用免费备用天气源，暂不提供台风路径和未来预测”。

## 三、发送设置测试
1. 点击左侧“发送设置”。
2. 分别测试以下组合并保存：
   - 仅勾选“简报内容”
   - 勾选“简报内容 + 天气情况”
   - 勾选“简报内容 + 天气情况 + 台风情况”
3. 刷新页面后检查勾选状态仍然保留。

## 四、与简报联动测试
1. 在“工作台”页面选择一个主题，例如“国外新闻”。
2. 确认“天气情况”页面已保存地区。
3. 点击“一键生成当日简报”。
4. 检查后端日志：
   - 应出现 `Weather report loaded for region=...`
   - 如和风天气失败，应出现 weather provider fallback 日志
5. 检查：
   - 邮件正文中是否附带天气和台风信息
   - 飞书消息中是否包含天气摘要和台风摘要

## 五、免费兜底测试
1. 删除 `.env` 中的 `QWEATHER_API_KEY`。
2. 保持 `WEATHER_PROVIDER=auto`，重启后端。
3. 再次查询天气。
4. 检查：
   - 页面仍能返回逐小时天气
   - 天气源显示 `Open-Meteo`
   - 页面出现“免费备用天气源”提示
   - 台风区域进入降级说明，而不是接口报错

## 六、强制主源测试
1. 设置：
   - `WEATHER_PROVIDER=qweather`
   - 不配置 `QWEATHER_API_KEY`
2. 重启后端，再次查询天气。
3. 检查：
   - 应返回明确错误，例如“未配置和风天气 QWEATHER_API_KEY”
   - 不应出现静默空白页面
